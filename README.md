# ZKiss

**오늘 같은 행사에 있는 사람과, 서로 원할 때만 조금씩 정보를 공개하는 번호팅.**

ZKiss는 대학 축제·일일호프 같은 오프라인 행사에서 쓰는 모바일 웹 매칭 서비스를 목표로 합니다. 참가자는 행사 QR로 들어와 사진 원본 대신 AI 인상 소개를 보고 관심을 표시합니다. 서로 관심이 맞으면 먼저 익명으로 대화하고, 두 사람이 별도로 동의할 때만 SNS ID를 공유합니다.

## 왜 만드나요?

일부 현장 번호팅에서는 매칭되지 않은 참가자의 사진이나 SNS ID도 운영진에게 먼저 전달됩니다. 그렇다고 얼굴 사진을 숨기고 아무 정보 없이 상대를 고르게 하면 첫 만남을 결정하기 어려울 수 있습니다.

ZKiss는 참가자에게는 **사진과 연락처를 먼저 공개하지 않고 대화를 시작할 선택권**을, 행사 운영자에게는 **참가자의 상세 개인정보를 직접 모으지 않고 행사를 운영할 방법**을 제안합니다. 이런 경험에 대한 참가자 수요와 운영자 도입 의사는 현장에서 검증해야 합니다.

## 어떻게 연결되나요?

1. **행사 입장:** QR로 모바일 웹에 접속하고 해당 행사의 참가 자격을 확인합니다. 실제 참가권 발급·검증 방식은 정해야 합니다.
2. **AI 인상 소개:** 사진 한 장으로 관찰 가능한 표정·옷차림·스타일을 짧게 소개합니다. 사진 원본은 분석 직후 삭제하고 후보에게 보여주거나 교환하지 않는 것이 제품 요구사항입니다. 삭제 범위와 외부 AI 제공자의 보관 정책은 확인이 필요합니다. **AI가 만든 문구는 사용자가 직접 수정할 수 없으며**, 사용자가 작성한 자기소개와 구분합니다.
3. **같은 행사에서 상호 선택:** 현재 행사에 참여하는 후보에게 관심을 표시합니다. 한쪽만 보낸 관심은 상대에게 알리지 않고, 서로 관심을 표시했을 때 연결하는 것이 목표입니다.
4. **연락처 없이 먼저 대화:** 매칭된 두 사람은 서비스 안에서 임시 텍스트 대화를 나눕니다. 대화가 맞지 않으면 SNS ID를 공개하지 않고 나갈 수 있습니다.
5. **별도 상호 동의로 SNS 공개:** 대화 후 두 사람이 각각 동의한 경우에만 SNS ID를 전달하는 것이 목표입니다. 매칭이나 결제는 공개 동의를 대신하지 않습니다.

## Midnight는 어디에 쓰이나요?

Midnight는 행사 참가 자격과 정해진 공개 승인 조건을 검증하는 프라이버시 계층으로 사용하려 합니다. AI는 사진을 인상 소개로 바꾸고, 서비스는 행사 범위·프로필·대화와 연락처 전달을 처리합니다. **ZK 증명만으로 사진 삭제, AI 소개의 정확성, SNS 전달의 비공개성이 보장되지는 않습니다.** 이를 위해 사진 처리 경계와 암호화·키 관리도 별도로 설계하고 검증해야 합니다.

## 사업 방향

초기 대상은 대학 축제·일일호프·교류 행사 참가자와 이를 운영하는 학생회·동아리·부스 운영팀입니다. 사업계획서 초안은 소액 참가비와 연결 이후 대화 연장 비용을 검토했지만, **가격·무료 범위·결제 시점은 정해지지 않았습니다.** 먼저 행사 현장에서 AI 소개의 선택 가치, 상호 매칭과 대화 경험, 운영자의 재사용 의사를 확인할 계획입니다.

제품 흐름, 개인정보 경계와 남은 검증 과제는 [PROJECT.md](PROJECT.md)에 정리했습니다.
